# Ваёбыж · rc-1.0.3

«Ваёбыж» — городская система событий, планов, друзей и обсуждений. «Кытчи» — её персональная технология подбора мероприятий.

Проект полностью переработан из раннего `events_soft`: вместо присваивания человеку непрозрачного `status_ml` используются только выбранные им интересы, свайпы и действия с конкретными событиями.

## Что уже работает

- карточки мероприятий с touch/mouse-свайпом: влево — `dismiss`, вправо или тап — подробности;
- кнопка «Пойду», список планов и фоновые in-app напоминания;
- друзья, входящие/исходящие запросы и видимость отмеченных планов;
- социальный сигнал «друзья идут» внутри рекомендаций Кытчи;
- пользовательские мероприятия со статусом `pending` и защищённым админ-решением;
- обсуждения, привязанные к городу, событию или площадке;
- динамические города и события KudaGo, опциональные ленты организаторов Timepad;
- Telegram-канал поверх того же рекомендательного ядра;
- подписанные анонимные сессии: в production нельзя писать действия от имени чужого пользователя;
- независимый вход через Google, Яндекс ID или GitHub с сохранением гостевых свайпов;
- интерфейс на русском, английском, китайском и удмуртском языках;
- адаптивный авангардный интерфейс и отдельная production-сборка;
- API- и unit-тесты, CI, healthchecks и контейнерный запуск.

## Как работает Кытчи

Кытчи не определяет «тип человека». Ранжирование складывается из понятных сигналов:

1. выбранные темы;
2. действия `open`, `like`, `save`, `attend`, `dismiss` с разной силой;
3. экспоненциальное ослабление старых действий;
4. планы принятых друзей;
5. популярность, близость даты, свежесть и события от сообщества;
6. диверсификация категорий и площадок, чтобы лента не превращалась в пузырь.

Смахнутое влево событие больше не возвращается. Посещение сильнее сохранения, сохранение сильнее открытия, а отрицательный свайп понижает похожие признаки. API возвращает `reasons` для каждой карточки и стратегию `kytchi-v1`.

## Архитектура

```text
React / Telegram
       │
       ▼
FastAPI · Ваёбыж API
       │
       ├── Кытчи: персональный и социальный ranking
       ├── планы / друзья / обсуждения / модерация
       └── in-app notification worker
       │
       ▼
PostgreSQL ◀── sync worker ◀── KudaGo / Timepad
```

- `frontend/` — React + TypeScript, свайп-лента и социальные сценарии;
- `backend/events_api/` — API, модели, Кытчи, провайдеры, workers и Telegram;
- `backend/tests/` — проверки рекомендаций и продуктовых API;
- `docker-compose.yml` — PostgreSQL, API, синхронизация, напоминания, Nginx и опциональный Telegram;
- `docker-compose.prod.yml` — автоматический HTTPS через Caddy на одном сервере;
- `deploy/helm/vayobyzh` — Kubernetes chart с миграциями, TLS, probes, NetworkPolicy, PDB/HPA и workers;
- `deploy/kubernetes` — воспроизводимая установка K3s/Helm и атомарный production rollout.

## Production-запуск

Локальный стек:

```bash
cp .env.example .env
docker compose up --build -d
```

Production на Ubuntu с автоматическим SSL:

```bash
cp .env.production.example .env
# заполните домен, секреты и нужные OAuth-пары
./deploy/ubuntu/up.sh
```

Полная инструкция, требования к серверу, systemd, обновления и резервные копии: [docs/UBUNTU_DEPLOY.md](docs/UBUNTU_DEPLOY.md).

Kubernetes/K3s, внешний PostgreSQL, GHCR, TLS, rollback и HA: [docs/KUBERNETES_DEPLOY.md](docs/KUBERNETES_DEPLOY.md).

API закрывает пользовательские записи подписанным bearer-токеном, административную модерацию — отдельным `X-Admin-Key`, внутреннюю проверку синхронизации — `X-Sync-Key`. Пароли Google, Яндекса и GitHub никогда не проходят через Ваёбыж, а access-токены провайдеров не сохраняются.

## Города и источники

По умолчанию синхронизируются Москва, Санкт-Петербург, Екатеринбург, Казань и Новосибирск. `SYNC_CITY_SLUGS` принимает любой актуальный slug KudaGo. Значение `all` включает все города, которые провайдер отдаёт сейчас, без изменения схемы или кода.

```env
SYNC_CITY_SLUGS=all
TIMEPAD_ORGANIZATION_IDS=1040,2040
```

Падение одного провайдера или одного города не останавливает остальные импорты. Повторная синхронизация обновляет событие по паре `source + source_id` и не создаёт дубли.

## Пользовательские события и модерация

`POST /api/v1/users/{user_id}/event-submissions` создаёт закрытую от публичной ленты заявку. Администратор получает очередь через `GET /api/v1/admin/event-submissions` и принимает решение через `POST /api/v1/admin/event-submissions/{event_id}/decision`. Только статус `published` попадает в каталог и Кытчи.

## Локальная разработка

Backend:

```bash
cd backend
python -m venv .venv
source .venv/bin/activate
pip install -e ".[dev]"
uvicorn events_api.main:app --reload
```

Frontend:

```bash
cd frontend
pnpm install
pnpm dev
```

Если API недоступен, сайт включает демонстрационный каталог, но production-сборка при доступном API хранит планы, связи, обсуждения, реакции и заявки в PostgreSQL.

## Проверки

```bash
cd backend && python -m pytest --cov=events_api
cd frontend && pnpm test && pnpm build
```

CI выполняет тесты и production-сборку на каждый push и pull request.
